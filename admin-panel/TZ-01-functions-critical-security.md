# ТЗ-01: Cloud Functions - критичные исправления безопасности

## Цель

Исправить серверные ошибки, где клиентские данные могут влиять на безопасность, права доступа или журнал действий.

## Важно перед началом

- Не менять логику входа владельца в admin-panel.
- Не трогать `admin-panel/src/services/authService.ts` в рамках этого ТЗ.
- Не добавлять новые роли без отдельного согласования.
- Все проверки прав должны выполняться на сервере, а не доверять payload от клиента.

## Файлы

- `functions/inviteAccess.js`
- `functions/index.js`

## Задача 1: запретить пустой HMAC secret

В `functions/inviteAccess.js` найти получение секрета для хэширования телефонов.

Нужно:

- Убрать fallback на пустую строку.
- Если `INVITE_ACCESS_HASH_SECRET` или Firebase Functions config не настроены, функция должна падать с понятной ошибкой.
- Не использовать слабый дефолтный секрет в коде.

Ожидаемое поведение:

- При настроенном секрете все работает как раньше.
- При пустом секрете invite-функции не создают предсказуемые хэши.

## Задача 2: убрать fallback `uid` в определении владельца записи

В `functions/index.js` найти `getRecordOwnerId`.

Нужно:

- Использовать только авторитетное поле `userId`.
- Если `userId` отсутствует, отказывать в доступе через ошибку.
- Не считать поле `uid` владельцем медиа-записи.

Ожидаемое поведение:

- Доступ к чужим медиа нельзя получить через подмену `uid`.
- Старые записи без `userId` должны быть явно видны как проблемные, а не молча разрешаться.

## Задача 3: `actorUid` брать только из `context.auth.uid`

В `functions/index.js` проверить callable functions, где используется `actorUid`, `adminUid`, `moderatedBy`, `updated_by` или похожие поля из `data`.

Нужно:

- Во всех callable functions требовать `context.auth`.
- Для автора действия использовать только `context.auth.uid`.
- Не принимать `actorUid` от клиента.

Ожидаемое поведение:

- Audit log показывает реального пользователя Firebase Auth.
- Клиент не может подставить чужой UID.

## Задача 4: атомарная запись `trust_tree` и `user_access`

В `functions/inviteAccess.js` проверить функцию выдачи root-доступа по телефонам.

Нужно:

- Заменить отдельные `set`/`update` на один multi-path update через `db.ref('/').update(updates)`.
- В один update должны попадать `trust_tree`, `trust_tree_index` и `user_access`.
- Если одна часть не может записаться, не должно быть частично записанного состояния.

## Проверка

- Запустить тесты или хотя бы lint/build для `functions`, если они есть в проекте.
- Проверить сценарий: пустой secret вызывает ошибку.
- Проверить сценарий: callable function записывает `actorUid` равный `context.auth.uid`.
- Проверить сценарий: запись без `userId` не дает доступ к медиа.

## Что не делать

- Не менять Firebase Rules в этом ТЗ.
- Не менять admin-panel auth.
- Не внедрять guest access в мобильном приложении.
