# ТЗ-04: Admin Panel - безопасная привязка к владельцу без потери доступа

## Цель

Усилить вход в admin-panel, но сохранить стабильный доступ владельца с текущего компьютера и через `VITE_ADMIN_SERVICE_EMAIL`.

## Критическое ограничение

В этом проекте нельзя молча удалять или ослаблять основной путь owner-доступа.

Перед изменением `admin-panel/src/services/authService.ts` нужно получить явное подтверждение владельца.

## Файлы

- `admin-panel/src/services/authService.ts`
- `admin-panel/src/App.tsx`
- `admin-panel/src/components/AppShell.tsx`
- `admin-panel/vite.config.ts`
- `admin-panel/start-admin-panel.bat`

## Задача 1: сохранить owner-доступ

Нужно проверить текущую логику:

- `VITE_ADMIN_SERVICE_EMAIL`.
- `isPrimaryServiceEmail`.
- UID владельца.
- роли `admin` и `moderator`.

Нельзя просто удалить email-проверку, пока нет подтвержденного альтернативного механизма.

## Задача 2: Google login без пароля

Если владелец подтверждает, можно сделать вход через Google OAuth.

Требования:

- Не показывать парольный экран, если выбран режим Google-only.
- После входа проверять UID и/или подтвержденный service email.
- Если пользователь не владелец и не имеет разрешенной роли - `signOut` и экран `Доступ запрещен`.
- Не раскрывать детали, какой именно UID или email ожидается.

## Задача 3: избежать бесконечного redirect loop

Если используется `signInWithRedirect`, нужно защититься от циклов:

- Не запускать redirect повторно, пока обрабатывается результат входа.
- Показывать состояние загрузки.
- После отказа не редиректить пользователя снова автоматически бесконечно.

## Задача 4: localhost-lock

Нужно явно убедиться, что dev server слушает только localhost.

Возможные меры:

- В `vite.config.ts` указать `server.host = 'localhost'`.
- В `.bat` запускать Vite с `--host localhost --port 5173`.

## Проверка

- Владелец входит со своего Google аккаунта.
- Владелец не теряет доступ при наличии `VITE_ADMIN_SERVICE_EMAIL`.
- Чужой Google аккаунт получает отказ.
- Нет бесконечного редиректа.
- Admin-panel не доступна из локальной сети по IP компьютера.

## Что не делать

- Не удалять `VITE_ADMIN_SERVICE_EMAIL` без явного решения владельца.
- Не менять роли `admin`/`moderator` без отдельного согласования.
- Не переносить admin mutations на Cloud Functions в этом ТЗ.
