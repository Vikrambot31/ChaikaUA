## Problem

EAS builds for v1.1.435 failed with Kotlin compilation error in `expo-modules-core`:

```
FAILURE: Build failed with an exception.
* What went wrong:
Execution failed for task ':expo-modules-core:compileReleaseKotlin'.

e: file:///home/expo/workingdir/build/node_modules/expo-modules-core/
   android/src/main/java/expo/modules/adapters/react/permissions/
   PermissionsService.kt:166:36

   Only safe (?.) or non-null asserted (!!.) calls are allowed on a
   nullable receiver of type Array<(out) String!>?
```

### Root Cause

Android SDK 35 added explicit `@Nullable` annotations to `PackageInfo.requestedPermissions`. The previous build (v1.1.434) used `compileSdkVersion 34`, so this issue didn't surface.

In `PermissionsService.kt:166`:
```kotlin
// OLD (fails with SDK 35):
return requestedPermissions?.contains(permission) == true

// The problem:
// - requestedPermissions is now explicitly @Nullable Array<String>?
// - The ?. operator returns a nullable result
// - .contains() on Array requires a non-null receiver
// - This violates Kotlin's null-safety rules
```

---

## Solution

Added postinstall patch `scripts/patch-expo-permissions-sdk35.js` that runs after `npm install`:

```kotlin
// FIXED (works with SDK 35):
return requestedPermissions?.toList()?.contains(permission) == true

// Why it works:
// - requestedPermissions?.toList() returns List<String>? (nullable)
// - List.contains() handles nullable chains correctly
// - Null-safety is preserved
```
