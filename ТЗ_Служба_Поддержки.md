## 1. Общее описание

Разработать систему поддержки пользователей, состоящую из двух частей:
- **Мобильное приложение:** новый экран «Служба Поддержки» с мини-чатом (последние 10 сообщений на экране)
- **Админ-панель:** новый раздел «Служба Поддержки» с лентой обращений, пагинацией и возможностью ответа

## 2. Мобильное приложение

### 2.1 Точка входа

- Новая кнопка **«Служба Поддержки»** (иконка `headset` или `help-circle`) в самом низу экрана `EditProfileScreen.tsx`
- Располагается после секции выбора языка (LanguageSelector), перед концом ScrollView
- Навигация: `navigation.navigate('SupportScreen')`
- Кнопка не отображается, если пользователь не авторизован

### 2.2 Экран «Служба Поддержки» (`SupportScreen.tsx`)

#### Макет экрана (сверху вниз):

```
┌─────────────────────────────────┐
│  ← Служба Поддержки            │  ← заголовок + кнопка назад
├─────────────────────────────────┤
│  Категория: [▼ Выберите тему]   │  ← выпадающий список категорий
├─────────────────────────────────┤
│  Статус: Відкрито / Закрито     │  ← статус текущего тикета (если есть)
├─────────────────────────────────┤
│                                 │
│  💬 Чат (последние 10 на экране)│  ← FlatList с сообщениями
│                                 │
│  [Користувач] Текст...    12:30 │
│  [Підтримка]  Відповідь.. 12:35 │
│                                 │
├─────────────────────────────────┤
│  [Введіть питання (до 500 сим)]│  ← TextInput (disabled если тикет closed)
│                     [Відправити]│  ← кнопка отправки
├─────────────────────────────────┤
│  Символів: 42/500               │  ← счётчик символов
└─────────────────────────────────┘
```

#### Логика работы:

1. **Категория** — обязательный выбор перед отправкой первого сообщения. После создания тикета — только для чтения (изменить нельзя)
2. **Поле ввода** — лимит **500 символов**. При превышении кнопка «Відправити» блокируется, текст счётчика становится красным
3. **Чат** — хранит все сообщения в RTDB, на экране отображает последние 10 (`limitToLast(10)`). Старые сообщения НЕ удаляются
4. **Сообщения** отображаются в стиле чат-пузырей:
   - Сообщения пользователя — справа, синий фон
   - Ответы поддержки — слева, серый фон
   - Каждое сообщение показывает время отправки
5. **Кнопка «Відправити»** — неактивна если: нет текста, не выбрана категория, превышен лимит символов, тикет закрыт
6. **Закрытый тикет** — поле ввода и кнопка отправки заблокированы, показывается текст «Звернення закрито. Ви можете створити нове.» и кнопка «Нове звернення»
7. **Индикатор** — если есть непрочитанный ответ от поддержки (`lastAdminMessage > lastReadByUser`), на кнопке в Профиле показывать бейдж (красная точка)
8. **Yellow list** — пользователь в `yellow_list` может читать переписку, но не может отправлять новые сообщения. Показывается текст: «Ваш акаунт обмежено. Зверніться до адміністратора»

## 3. Firebase RTDB — Структура данных

### 3.1 Коллекция `/support_tickets/{ticketId}`

```typescript
interface SupportTicket {
  ticketId: string            // auto-generated push key
  userId: string              // userId автора
  userName: string            // имя пользователя (для отображения в админке)
  category: SupportCategory   // ключ категории (registration, profile, ...)
  status: 'open' | 'closed'  // статус обращения
  createdAt: number           // timestamp создания
  updatedAt: number           // timestamp последнего сообщения
  lastAdminMessage: number    // timestamp последнего сообщения от админа (0 если нет)
  lastReadByUser: number      // timestamp последнего прочтения пользователем
  lastUserMessage: number     // timestamp последнего сообщения от юзера (0 если нет)
  lastReadByAdmin: number     // timestamp последнего прочтения админом
}
```

**Вычисление непрочитанных (вместо boolean-флагов):**
- Непрочитанные для юзера: `lastAdminMessage > lastReadByUser`
- Непрочитанные для админа: `lastUserMessage > lastReadByAdmin`

**Примечание:** Каждый пользователь может иметь только **одно активное обращение** (`status: 'open'`). Для нового обращения предыдущее автоматически закрывается.

### 3.2 Коллекция `/support_messages/{ticketId}/{messageId}`

```typescript
interface SupportMessage {
  messageId: string           // auto-generated push key
  ticketId: string            // ← ссылка на тикет
  senderId: string            // userId отправителя (userId или 'admin_{adminUid}')
  senderRole: 'user' | 'admin'
  text: string                // текст сообщения (до 500 символов)
  timestamp: number           // время отправки
}
```

### 3.3 Хранение сообщений

- Все сообщения сохраняются в RTDB **без удаления**
- Мобильное приложение подписывается с `limitToLast(10)` — показывает последние 10
- Админ-панель загружает все сообщения тикета (без лимита)
- Это исключает потерю контекста переписки и race conditions при удалении

### 3.4 Правила безопасности (firebase.rules.json)

```json
"support_tickets": {
  ".indexOn": ["userId", "status", "updatedAt"],
  "$ticketId": {
    ".read": "auth != null && (data.child('userId').val() === auth.uid || root.child('user_roles').child(auth.uid).child('role').val() === 'admin')",
    ".write": "auth != null && ((!data.exists() && newData.child('userId').val() === auth.uid) || root.child('user_roles').child(auth.uid).child('role').val() === 'admin')",
    ".validate": "newData.hasChildren(['ticketId', 'userId', 'userName', 'category', 'status', 'createdAt', 'updatedAt'])",
    "status": {
      ".write": "auth != null && root.child('user_roles').child(auth.uid).child('role').val() === 'admin'",
      ".validate": "newData.val() === 'open' || newData.val() === 'closed'"
    },
    "text": {
      ".validate": "newData.isString() && newData.val().length <= 500"
    },
    "category": {
      ".validate": "newData.isString() && newData.val().length > 0 && newData.val().length <= 30"
    }
  }
},
"support_messages": {
  "$ticketId": {
    ".read": "auth != null && (root.child('support_tickets').child($ticketId).child('userId').val() === auth.uid || root.child('user_roles').child(auth.uid).child('role').val() === 'admin')",
    ".indexOn": ["timestamp"],
    "$messageId": {
      ".write": "auth != null && (root.child('support_tickets').child($ticketId).child('userId').val() === auth.uid || root.child('user_roles').child(auth.uid).child('role').val() === 'admin')",
      ".validate": "newData.hasChildren(['messageId', 'ticketId', 'senderId', 'senderRole', 'text', 'timestamp']) && newData.child('text').val().length <= 500 && (newData.child('senderRole').val() === 'user' || newData.child('senderRole').val() === 'admin')"
    }
  }
}
```

**Ключевые улучшения правил:**
- `.write` на тикет: создать может только владелец (`!data.exists() && newData.userId === auth.uid`), изменять — только admin
- `.validate` проверяет обязательные поля, типы, длину текста
- `status` — отдельное правило записи: менять может только admin
- `.indexOn` для эффективных запросов

#### Функционал:

1. **Лента обращений** (левая колонка):
   - Список тикетов с **пагинацией по 20** (`limitToLast(20)`, `endBefore` для следующей страницы)
   - Сортировка по `updatedAt` (новые сверху)
   - Индикатор непрочитанных (● синяя точка) для `lastUserMessage > lastReadByAdmin`
   - Показывает: имя пользователя, категорию, превью последнего сообщения, время
   - **Фильтр по статусу:** Все / Відкриті / Закриті
   - **Фильтр по категории**

2. **Переписка** (правая колонка):
   - Отображает **все сообщения** выбранного тикета (без лимита)
   - Информация: категория, статус, userId, дата создания
   - **Поле ответа** — TextArea без лимита символов (для админа)
   - **Кнопка «Відправити»** — отправляет ответ с `senderRole: 'admin'`, обновляет `lastAdminMessage` в тикете
   - **Кнопка «Закрити звернення»** — меняет `status: 'closed'`
   - При открытии переписки автоматически обновляет `lastReadByAdmin: serverTimestamp`

3. **Статистика** (нижняя панель):
   - Всього звернень
   - Відкритих звернень
   - Звернень за сьогодні

## 7. Real-time подписки

### Мобильное приложение:
- `onValue` на `query(ref('support_tickets'), orderByChild('userId'), equalTo(auth.uid))` — для проверки непрочитанных и загрузки тикета
- `onValue` на `query(ref('support_messages/' + ticketId), orderByChild('timestamp'), limitToLast(10))` — для чата в реальном времени

### Админ-панель:
- `onValue` на `query(ref('support_tickets'), orderByChild('updatedAt'), limitToLast(20))` — пагинированная лента
- `onValue` на `ref('support_messages/' + ticketId)` — все сообщения выбранного тикета

**Важно:** Все подписки отписываются (`off()`) при unmount компонента или смене тикета.

## 8. Пограничные случаи

| Сценарий | Поведение |
|----------|-----------|
| Пользователь не авторизован | Кнопка «Служба Поддержки» не отображается |
| Пользователь в yellow_list | Может читать, но не может отправлять. Toast: «Ваш акаунт обмежено» |
| Нет интернета | Показать toast «Немає з'єднання» |
| Ввод > 500 символов | Кнопка «Відправити» неактивна, счётчик символов красный |
| Категория не выбрана | Кнопка «Відправити» неактивна |
| Уже есть открытый тикет | Открывается существующий, новый не создаётся |
| Админ закрыл тикет | Поле ввода заблокировано, текст «Звернення закрито», кнопка «Нове звернення» |
| Пользователь создаёт новый при закрытом | Старый тикет остаётся в истории, создаётся новый |
| Одновременная отправка (юзер + админ) | Нет race condition — сообщения не удаляются, push() гарантирует уникальность |
| Много сообщений в тикете | Мобильное: `limitToLast(10)`. Админка: все |
