## Вступ

Проект ChaikaUA — це великий набір модулів: мобільний додаток, адмін-панель, сайт, Firebase-функції.  
Розробник витрачає час на:

- ручне тестування та перевірку правил Firebase;
- модерацію фото/контенту;
- деплой правил, функцій, білдів;
- моніторинг помилок і сповіщень;
- рутинні зміни в коді (додавання полів, дублювання логіки).

**Автономні ІІ-агенти** можуть виконувати ці задачі за командою, залишаючи розробнику творчу роботу.

## Кандидати на автоагентів

### 3.1 QA / Тестувальник

**Призначення:** автоматична перевірка правил Firebase, регресійне тестування, перевірка типів і контрактів.

**Які команди може виконувати:**
- `npm run test:rules:emulator` — перевірка правил у емуляторі
- `npx jest firebaseRulesSecurity --runInBand` — тести безпеки
- `npm run type-check` — перевірка TypeScript
- `npm test` — запуск усіх тестів

**Файли, які має сенс редагувати/створювати:**
- `src/__tests__/*.ts` — нові тест-кейси
- `scripts/run-rules-emulator-tests.mjs` — покращення тестів правил
- `jest.config.js` — конфігурація тестів

---

### 3.2 Firebase DevOps

**Призначення:** деплой правил, бекапи, міграції даних, перевірка конфігурації.

**Команди:**
- `npm run deploy:prod:checked` — повний деплой з перевірками
- `npm run rules:check` / `rules:check:storage` — валідація правил
- `npm run migrate:*` — міграції даних

**Файли:**
- `firebase.rules.json` — правила RTDB (обережно!)
- `storage.rules` — правила Storage
- `firebase.json` — конфігурація Firebase
- `scripts/migrate-*.mjs` — скрипти міграцій
- `functions/` — Cloud Functions (потрібен окремий агент)

---

### 3.3 Модератор контенту

**Призначення:** перевірка фото, скарг, контенту на порушення; автоматичне блокування небезпечного контенту.

**Команди:**
- `npm run moderation` — CLI-модерація
- `npm run audit:community-photos` — аудит фото спільноти

**Файли:**
- `scripts/moderation-cli.mjs` — основний скрипт модерації
- `scripts/audit-community-photos.mjs` — аудит
- `src/services/moderatorService.ts` — сервіс модерації

- `src/screens/Moderaciya-Foto.tsx` — екран модерації
- `src/screens/ServiceModerationScreen.tsx` — модерація послуг
- `src/utils/imageSafety.ts` — безпека зображень

## Висновки

1. **Пріоритетні агенти** (економлять найбільше часу):
   - DevOps (деплой + перевірки)
   - QA / Тестувальник
   - Модератор контенту
   - Безпека та аудит

2. **Середня складність впровадження:**
   - Кожен агент — це окремий набір інструкцій (prompt-ів) та можливо окремий скрипт запуску.
   - Для більшості агентів не потрібно змінювати код проекту — достатньо використовувати існуючі скрипти та сервіси.
   - Для агентів «Новини», «Аналітика», «ОСББ» можна додати нові скрипти-автоматизації.

3. **Безпека:**
   - Агенти, що працюють з `firebase.rules.json` та `authService`, мають мати жорсткі обмеження (guardrails).
   - Жоден агент не повинен змінювати правила без явного дозволу користувача.

4. **Рекомендація:**
   - Створити окрему директорію `agents/` з файлами інструкцій для кожного агента (наприклад, `agents/qa-agent.md`, `agents/devops-agent.md` тощо).
   - Для запуску агентів використовувати один з підходів:
     - **CLI-команда** (наприклад, `npm run agent:qa`)
     - **Окремі Node.js скрипти**, що викликають API ІІ-моделі
     - **Інтеграція з IDE** (наприклад, VS Code tasks)
