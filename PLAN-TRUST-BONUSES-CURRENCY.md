# План и ТЗ: две валюты — «Бонусы доверия» и «Промо-кредиты»

Дата: 2026-06-04 (v2 — разделение валют)

---

## 1. Концепция: две разные валюты

Приложение Chaika Life использует **две раздельные валюты** с разной природой и назначением:

| | Бонусы доверия | Промо-кредиты |
| --- | --- | --- |
| **Суть** | Репутация за реальные дела | Рекламная валюта |
| **Как получить** | Автоматически за полезные действия | Купить у администратора за реальные деньги |
| **Кто начисляет** | Cloud Functions автоматически | Администратор вручную после оплаты |
| **На что тратить** | Топ-анкета в «Контактах», топ своих услуг (когда накоплено много) | Любое платное продвижение: бизнес, салоны, детский раздел |
| **Можно ли купить** | Нет, только заработать | Да, через связь с админом |
| **Лимиты** | Недельные потолки | Без лимитов (сколько купил — столько есть) |
| **Смысл для сообщества** | Доверие остаётся честным сигналом | Бизнесу — понятный способ продвигаться |

**Главное правило:** бонусы доверия нельзя купить за деньги, а промо-кредиты нельзя заработать бесплатными действиями. Это гарантирует, что «доверие» — настоящее, а «реклама» — прозрачная.

## 3. ВАЛЮТА 1: Бонусы доверия

### 3.1. Принцип

Бонусы доверия начисляются **автоматически** Cloud Functions за реальные полезные действия. Пользователь не может повлиять на начисление кроме как действительно помочь, получить благодарность или пригласить проверенного жителя.

### 3.2. Таблица начислений

Все значения подобраны так, чтобы:
- за неделю активный житель мог заработать 100–250 бонусов;
- за месяц стабильной активности — выйти на уровень `active_resident` (500);
- за полгода помощи — достичь `guardian` (2000);
- `ambassador` (5000) — только по-настоящему вовлечённые жители.

| Действие | Бонусы | Условие | Категория |
| --- | ---: | --- | --- |
| **Помощь по заявке** | | | `help` |
| Откликнулся на заявку («Я могу помочь») | +5 | один раз на заявку; предварительный отклик | help |
| Автор подтвердил помощь | +20 | основное начисление помощнику | help |
| Автор закрыл заявку «вопрос решён» | +5 | автору за корректное закрытие | help |
| **Благодарности** | | | `gratitude` |
| Автор оставил благодарность помощнику | +10 | только после закрытия заявки | gratitude |
| Получил «спасибо» в профиле от другого жителя | +3 | не чаще 1 раза от одного жителя в сутки | gratitude |
| **Приглашения** | | | `invites` |
| Пригласил нового жителя (доступ одобрен) | +50 | только после прохождения проверки | invites |
| **Лайки / реакции** | | | `likes` |
| Получил лайк на профиль | +2 | не чаще 1 лайка от одного пользователя в сутки | likes |
| Получил лайк на заявку/публикацию | +1 | лимит 10 лайков в сутки на один пост | likes |
| **Активность** | | | `activity` |
| Первый вход в приложение за день | +1 | один раз в сутки (серверное время) | activity |
| Заполнил профиль полностью (фото + описание + контакты) | +30 | разовый бонус | activity |
| Первая заявка (любой тип) | +10 | разовый бонус | activity |
| Первый отклик на чужую заявку | +10 | разовый бонус | activity |

### 3.3. Недельные лимиты бесплатных бонусов

| Категория | Лимит / неделю | Комментарий |
| --- | ---: | --- |
| help (помощь) | 100 | ≈5 подтверждённых помощей |
| gratitude (благодарности) | 50 | ≈5 благодарностей |
| likes (лайки/реакции) | 30 | защита от обмена лайками |
| invites (приглашения) | 150 | ≈3 приглашения |
| activity (активность) | 7 | ежедневный вход |
| **Общий бесплатный лимит** | **250** | мягкий недельный потолок |

При превышении лимита события записываются в историю, но бонусы не начисляются. В UI: «Лимит бесплатных бонусов на этой неделе исчерпан. Обнуление через X дней».

**Неделя считается по серверному времени** (UTC+2, Украина). Клиент не может сбросить лимит сменой часового пояса.

### 3.4. Ограничения для новых аккаунтов

Действуют до подтверждения доступа поручителем (не по дате регистрации — бот не «отлежится» и не обойдёт):

- общий бесплатный лимит: 100 бонусов;
- нельзя обменивать бонусы на топ-позиции;
- нельзя передавать бонусы другим пользователям.

### 3.5. На что можно обменять бонусы доверия

Когда у жителя накопилось достаточно бонусов, он может обменять их на **личную видимость** (не коммерческую):

#### а) Топ-анкета в «Контактах Чайки»

Профиль показывается в верхнем блоке экрана «Контакты Чайки».

| Срок | Цена (бонусы) | Минимальный бейдж |
| --- | ---: | --- |
| 24 часа | 80 | `good_neighbor` (100+) |
| 3 дня | 200 | `active_resident` (500+) |
| 7 дней | 420 | `active_resident` (500+) |

Ограничения:
- одно активное размещение на пользователя;
- максимум 5 топ-профилей одновременно;
- фото и профиль должны пройти модерацию;
- обязательный бейдж «В топе».

#### б) Топ своих услуг / предложений

Если у жителя есть своя карточка услуги (не бизнес-аккаунт, а личное предложение — репетитор, няня, мастер), он может поднять её.

| Срок | Цена (бонусы) | Минимальный бейдж |
| --- | ---: | --- |
| 24 часа | 100 | `active_resident` (500+) |
| 3 дня | 250 | `active_resident` (500+) |
| 7 дней | 500 | `guardian` (2000+) |

Ограничения:
- только владелец карточки;
- карточка `approved`;
- бейдж «Продвинуто бонусами».

**Важно:** бонусы доверия **не дают доступа** к коммерческому продвижению в разделах «Бизнес», «Салоны красоты», «Всё для детей». Для этого — промо-кредиты.

### 3.6. Бейджи (без изменений)

| Бейдж | Порог | Значение |
| --- | ---: | --- |
| `newcomer` | 0 | Новичок |
| `good_neighbor` | 100 | Хороший сосед |
| `active_resident` | 500 | Активный житель |
| `guardian` | 2 000 | Хранитель |
| `ambassador` | 5 000 | Посол Чайки |

### 3.7. Защита от накрутки

Обязательные правила:

1. Нельзя получить бонусы за помощь самому себе.
2. Один помощник = один бонус по одной заявке (idempotency-key: `requestId+helperUid`).
3. Автор подтверждает максимум 1 основного + 2 дополнительных помощника.
4. Повторные заявки между одной парой аккаунтов чаще 3 раз в неделю → на ручную проверку.
5. **Использовать `trust_tree` (`depthToRoot/rootPath`)**: вес подтверждения зависит от расстояния в дереве доверия. Если аккаунты — соседи в цепочке приглашений, подтверждения помощи проходят фоновую проверку на кольца.
6. Аккаунты с одинаковым телефоном/устройством → бонусы только после модерации.
7. Все начисления — **только через Cloud Functions с RTDB-транзакциями**. Клиент не пишет в `user_bonuses` напрямую.
8. Каждая функция начисления — **идемпотентна** (ретрай не начислит дважды).

## 4. ВАЛЮТА 2: Промо-кредиты

### 4.1. Принцип

Промо-кредиты покупаются за реальные деньги через связь с администратором. Это рекламная валюта для бизнеса и коммерческих предложений.

### 4.2. Как купить промо-кредиты — чат «По вопросам рекламы»

Процесс строится на **копии паттерна чата «Службы поддержки»**:

#### Вход для пользователя (мобильное приложение)

В профиле пользователя (или в кошельке) — новая кнопка:
- Иконка: `bullhorn` или `currency-usd` (MaterialCommunityIcons)
- Текст: «По вопросам рекламы» / «З питань реклами» / «Advertising inquiries»
- При нажатии → открывается `AdChatScreen` (копия `SupportScreen` с адаптацией)

#### Чат пользователя (`AdChatScreen`)

Аналог `SupportScreen`, но:
- Заголовок: «Реклама и продвижение»
- Категории (вместо категорий поддержки):
  - `buy_credits` — Купить промо-кредиты
  - `promote_business` — Продвинуть бизнес
  - `promote_beauty` — Продвинуть салон/мастера
  - `promote_kids` — Продвинуть детский раздел
  - `partnership` — Партнёрство
  - `other_ad` — Другой вопрос
- Структура сообщений — та же: `senderId`, `senderRole`, `text`, `timestamp`
- Максимум 500 символов
- Статус тикета: `open` / `closed`
- Индикатор непрочитанных сообщений от админа

#### Панель в Админ-панели

Новая страница `AdChatPage` — копия `SupportPage` с адаптацией:
- Левая колонка: список тикетов рекламного чата (фильтр по статусу, категории)
- Правая колонка: переписка + кнопки действий
- Кнопки админа:
  - «Ответить» (текстовое сообщение)
  - «Начислить кредиты» (ввод суммы + причина → пишет в `promo_credits/{uid}`)
  - «Закрыть тикет»
- Статистика: всего тикетов, открытых, сегодня

#### RTDB-структура рекламного чата

```
/ad_ticket_ref/{userId} → ticketId

/ad_tickets/{ticketId}
├─ ticketId: string
├─ userId: string
├─ userName: string
├─ category: string (buy_credits|promote_business|promote_beauty|promote_kids|partnership|other_ad)
├─ status: 'open' | 'closed'
├─ createdAt: number
├─ updatedAt: number
├─ lastAdminMessage: number
├─ lastReadByUser: number
├─ lastUserMessage: number
└─ lastReadByAdmin: number

/ad_messages/{ticketId}/{messageId}
├─ messageId: string
├─ ticketId: string
├─ senderId: string
├─ senderRole: 'user' | 'admin'
├─ text: string (max 500)
└─ timestamp: number
```

Права доступа — аналогично `support_tickets`/`support_messages`.

### 4.3. Курс промо-кредитов

Курс хранится в Remote Config или RTDB-конфиге, не зашит в UI:

| Пакет | Кредиты | Цена (грн) | Экономия |
| --- | ---: | ---: | --- |
| Стартовый | 100 | 20 | — |
| Базовый | 500 | 90 | 10% |
| Бизнес | 1 000 | 170 | 15% |
| Партнёр | 3 000 | 450 | 25% |

### 4.4. На что тратить промо-кредиты

Промо-кредиты дают доступ к **коммерческому продвижению** в разделах:

#### Бизнес на Чайке

| Срок | Цена (кредиты) |
| --- | ---: |
| 24 часа | 120 |
| 3 дня | 300 |
| 7 дней | 650 |
| 30 дней | 2 200 |

#### Салоны красоты

| Тип | 24 часа | 7 дней |
| --- | ---: | ---: |
| Салон | 120 | 650 |
| Мастер | 90 | 480 |
| Акция | 100 | 550 |

#### Всё для детей

| Тип | 24 часа | 7 дней |
| --- | ---: | ---: |
| Детское место | 120 | 650 |
| Кружок/секция | 100 | 550 |
| Мероприятие | 80 | 420 |
| Акция | 100 | 550 |

Ограничения:
- только владелец карточки может продвигать;
- карточка должна быть `approved`;
- обязательный бейдж «В топе» / «Партнёр»;
- запрещены медицинские/финансовые/сомнительные обещания без модерации;
- детский раздел: топ-блок не более 3 карточек, чтобы раздел оставался полезным.

## 5. Где показывать

### 5.1. Профиль пользователя

#### Карточка «Бонусы за доверие» (существующая)

Остаётся в профиле, показывает баланс и бейдж. При нажатии → экран деталей бонусов:
- текущий баланс и бейдж;
- сколько получено за неделю (прогресс-бар до лимита);
- разбивка по категориям (help, gratitude, invites, likes, activity);
- история начислений;
- кнопка «Обменять бонусы» (если достаточно для топа).

#### Новый экран «Мої Фінанси і кредити» (`FinancesScreen`)

Отдельная кнопка в разделе «Профиль Пользователя» ниже карточки бонусов. Это **главный экран промо-кредитов**.

**Верхний блок — Счёт:**
- Баланс промо-кредитов (крупная цифра).
- Сколько всего пополнено за всё время.
- Дата последнего пополнения.
- Кнопка «Пополнить баланс» → открывает `AdChatScreen` (чат с админом).

**Раздел — Активные подписки:**
- Список текущих подписок (продвижений) с датами окончания.
- Статус: «Активна», «Истекает через N дней», «Истекла».
- Кнопка «Продлить» → списание кредитов / переход в чат.

**Раздел — На что потратить:**
- Карточки-категории с ценами:
  - 📍 Бизнес на Чайке — от 120 кредитов/день
  - 💇 Салоны красоты — от 90 кредитов/день
  - 🧒 Всё для детей — от 80 кредитов/день
- По нажатию → экран выбора карточки для продвижения.
- Созданные заявки на продвижение **проходят модерацию** перед публикацией.

**Раздел — История операций:**
- Все пополнения и списания кредитов.
- Фильтр по типу: пополнения / списания / все.

### 5.2. Подписки по промо-кредитам

Промо-продвижения работают как **месячные подписки** с автоматическим продлением (если хватает кредитов) или предупреждением.

#### Механика подписки

1. Пользователь выбирает продвижение на 30 дней → создаётся подписка.
2. Кредиты списываются сразу за полный период.
3. Подписка имеет `startsAt`, `expiresAt`, `autoRenew` (boolean).

#### Уведомления об окончании

Система отправляет push-уведомления + показывает модальное окно на экране «Фінанси»:

| Дней до окончания | Действие |
| --- | --- |
| 5 дней | Push-уведомление: «Ваша подписка на продвижение [название] истекает через 5 дней. Хотите продлить?» |
| 4 дня | Push-уведомление (если не продлено) |
| 3 дня | Push + модальное окно при входе в «Фінанси» |
| 2 дня | Push-уведомление |
| 1 день | Push + модальное окно: «Подписка истекает завтра! Пополните баланс, чтобы продлить.» |
| 0 (истекла) | Push: «Подписка на [название] завершена. Продвижение снято.» |

#### Автопродление

- Если `autoRenew = true` и на балансе достаточно кредитов → подписка продлевается автоматически за сутки до окончания.
- Если кредитов не хватает → уведомление: «Недостаточно кредитов для продления. Пополните баланс.» + ссылка на чат с админом.
- Пользователь может отключить `autoRenew` в любой момент.

#### RTDB-структура подписок: `promo_subscriptions/{uid}/{subscriptionId}`

```json
{
  "uid": "userUid",
  "targetType": "business|beauty|kids",
  "targetId": "listingId",
  "screen": "business|beauty|kids",
  "plan": "30d",
  "creditsPerPeriod": 2200,
  "autoRenew": true,
  "status": "active|expiring|expired|cancelled",
  "startsAt": 0,
  "expiresAt": 0,
  "renewedAt": 0,
  "renewCount": 0,
  "notifiedDays": [5, 4, 3, 2, 1],
  "createdAt": 0,
  "updatedAt": 0
}
```

#### Cloud Functions для подписок

- **`checkExpiringSubscriptions`** — Scheduled (раз в день, утро):
  - Находит подписки с `expiresAt` через 5/4/3/2/1 дней.
  - Отправляет push-уведомления.
  - Записывает отправленный день в `notifiedDays`.

- **`autoRenewSubscriptions`** — Scheduled (раз в день, после `checkExpiring`):
  - Находит подписки с `autoRenew=true` и `expiresAt` завтра.
  - Если хватает кредитов → списывает, продлевает `expiresAt` на 30 дней.
  - Если не хватает → уведомление + `status=expiring`.

- **`expireSubscriptions`** — Scheduled (раз в час):
  - Находит `status=active|expiring` + `expiresAt < now`.
  - Переводит в `expired`, снимает продвижение.

### 5.2. Карточки заявок помощи

Во всех типах заявок, где жители помогают друг другу:

- срочная помощь, помощь с детьми, доставка/покупки, ремонт, помощь пожилым, документы/перевод, переезд/уборка, потеряно/найдено и др.

Блок в карточке заявки:
- «Я могу помочь» (отклик → +5 бонусов)
- «Подтвердить помощь» (автор → помощник получает +20)
- «Поблагодарить помощника» (после закрытия → +10)
- «Вопрос решён» (закрытие → автор +5)

Бонусы не начисляются за просмотр или нажатие без подтверждения.

### 5.3. Экраны продвижения

Все экраны с топ-блоками:

- **Контакты Чайки** — за бонусы доверия (личная видимость)
- **Бизнес на Чайке** — за промо-кредиты
- **Салоны красоты** — за промо-кредиты
- **Всё для детей** — за промо-кредиты

Любое продвижение помечено бейджем: «В топе», «Продвинуто бонусами», «Партнёр». Скрытое продвижение запрещено.

## 6. Модель данных

### 6.1. Бонусы доверия: `user_bonuses/{uid}`

Расширение существующей структуры:

```json
{
  "total": 0,
  "available": 0,
  "earned": {
    "total": 0,
    "weeklyTotal": 0,
    "weekKey": "2026-W23"
  },
  "invites": { "count": 0, "points": 0 },
  "likes": { "count": 0, "points": 0 },
  "help": { "count": 0, "points": 0 },
  "gratitude": { "count": 0, "points": 0 },
  "activity": { "count": 0, "points": 0 },
  "spent": {
    "total": 0,
    "contactsTop": 0,
    "servicesTop": 0
  },
  "badge": "newcomer",
  "accessConfirmed": false,
  "updatedAt": 0
}
```

Формула: `available = total - spent.total`

### 6.2. Промо-кредиты: `promo_credits/{uid}`

```json
{
  "balance": 0,
  "lifetime": 0,
  "spent": {
    "total": 0,
    "businessTop": 0,
    "beautyTop": 0,
    "kidsTop": 0
  },
  "updatedAt": 0
}
```

### 6.3. История операций (общая): `bonus_transactions/{uid}/{transactionId}`

```json
{
  "type": "earn|spend|topup|admin_adjustment|refund",
  "currency": "trust|promo",
  "category": "help|gratitude|invite|like|activity|contacts_top|services_top|business_top|beauty_top|kids_top|purchase",
  "points": 20,
  "balanceAfter": 340,
  "sourceId": "requestId-or-placementId-or-ticketId",
  "sourceType": "request|profile|business|beauty|kids|admin|ad_ticket",
  "status": "completed|pending|cancelled|refunded",
  "createdAt": 0,
  "createdBy": "uid-or-system",
  "note": "optional"
}
```

**Важно:** `balanceAfter` — кэш для быстрого показа. Источник истины — RTDB-транзакция в `user_bonuses` / `promo_credits`. Функции начисления и списания используют `transaction()` для атомарности.

### 6.4. Топ-размещения: `bonus_promotions/{promotionId}`

```json
{
  "uid": "buyerUid",
  "currency": "trust|promo",
  "targetType": "profile|service|business|beauty|kids",
  "targetId": "profileUid-or-listingId",
  "screen": "contacts|business|beauty|kids",
  "pointsSpent": 120,
  "status": "active|expired|cancelled|moderation",
  "startsAt": 0,
  "expiresAt": 0,
  "createdAt": 0,
  "moderationStatus": "approved|pending|rejected",
  "badge": "top|bonus_promoted|partner"
}
```

Экраны фильтруют: `status=active`, `moderationStatus=approved`, `expiresAt > now`. Крон (`expireBonusPromotions`) работает как фоновая уборка, но не как условие исчезновения — клиент проверяет `expiresAt` самостоятельно.

### 6.5. Подписки: `promo_subscriptions/{uid}/{subscriptionId}`

Структура описана в §5.2. Это отдельный узел от `bonus_promotions` — подписка управляет жизненным циклом продвижения (продление, уведомления, авторенью), а `bonus_promotions` — сам факт размещения.

## 8. Cloud Functions

### 8.1. Бонусы доверия (автоматические)

#### `awardHelpBonus`

Начисляет бонусы помощнику после подтверждения.

Проверки:
- авторизация;
- заявка существует;
- `helperUid ≠ authorUid`;
- idempotency-key: `requestId+helperUid` (ретрай не начислит дважды);
- недельный лимит категории `help` не превышен;
- недельный лимит общий не превышен;
- `weekKey` считается по серверному времени (UTC+2);
- RTDB `transaction()` для атомарного обновления баланса.

#### `confirmHelperForRequest`

Автор подтверждает помощника:
- пишет `help_responses/{requestId}/{helperUid}`;
- вызывает `awardHelpBonus`;
- пишет `bonus_transactions/{helperUid}`;
- отправляет push-уведомление помощнику.

#### `awardGratitudeBonus`

После закрытия заявки, автор благодарит:
- idempotency: `requestId+authorUid+helperUid`;
- проверка лимита `gratitude`;
- начисление +10 помощнику.

#### `awardLikeBonus`

При получении лайка:
- не чаще 1 от одного пользователя в сутки;
- проверка лимита `likes`.

#### `awardActivityBonus`

Ежедневный вход, разовые бонусы за первые действия:
- idempotency: `uid+date` для дневного входа;
- одноразовые: `uid+milestone` (profile_complete, first_request, first_response).

### 8.2. Промо-кредиты (через админа)

#### `adminGrantPromoCredits`

Администратор начисляет кредиты:
- только `role=admin`;
- обязательная причина и привязка к тикету рекламного чата (`ad_ticket`);
- RTDB `transaction()`;
- запись в `bonus_transactions` с `currency=promo`.

#### `adminAdjustPromoCredits`

Списание, возврат, корректировка:
- причина обязательна;
- запись в историю.

### 8.3. Продвижение (общее)

#### `purchaseBonusPromotion`

Списывает бонусы или кредиты и создаёт промо-размещение:
- определяет `currency` по `targetType` (profile/service → trust, business/beauty/kids → promo);
- проверяет `available` / `balance`;
- проверяет минимальный бейдж (для trust-продвижений);
- карточка прошла модерацию;
- нет конфликтующего активного продвижения;
- RTDB `transaction()` для атомарного списания;
- создаёт `bonus_promotions/{id}`.

#### `expireBonusPromotions`

Scheduled-функция (раз в час):
- находит `status=active` + `expiresAt < now`;
- переводит в `expired`;
- нужна для метрик и уборки, не для показа (клиент сам фильтрует по `expiresAt`).

## 10. UI-сценарии

### 10.1. Житель помогает по заявке

1. Открывает заявку → «Я могу помочь» → +5 бонусов доверия (отклик).
2. Автор видит список откликов → «Подтвердить помощь» → помощник получает +20.
3. Автор закрывает заявку «Вопрос решён» → автор +5.
4. Автор благодарит помощника → помощник +10.

### 10.2. Житель хочет поднять свой профиль в Контактах

1. Открывает «Бонусы доверия» → «Обменять бонусы».
2. Выбирает «Топ-анкета в Контактах».
3. Видит цену, срок, проверку бейджа.
4. Подтверждает списание.
5. Профиль появляется в топе с бейджем «В топе».

### 10.3. Бизнес хочет продвинуться

1. Открывает профиль → «Промо-кредиты» → «Купить кредиты».
2. Попадает в чат «По вопросам рекламы» (AdChatScreen).
3. Выбирает категорию «Купить промо-кредиты», пишет админу.
4. Админ отвечает в чате, согласовывает оплату.
5. После оплаты админ нажимает «Начислить кредиты» → баланс обновляется.
6. Бизнес возвращается в «Промо-кредиты» → «Продвинуть» → выбирает карточку и срок.

### 10.4. Админ работает с рекламными тикетами

1. Открывает Админ-панель → «Рекламный чат» (AdChatPage).
2. Видит список тикетов (аналог SupportPage).
3. Открывает тикет, отвечает.
4. Нажимает «Начислить кредиты» → вводит сумму и причину.
5. Система начисляет, пишет в историю.

### 10.5. Админ мониторит бонусы

1. Открывает «Бонусы и кредиты» (BonusCreditsPage).
2. Видит таблицу пользователей с балансами.
3. Кликает на пользователя → видит историю.
4. Может начислить/списать вручную с причиной.

## 12. Критерии готовности

- [ ] Пользователь видит баланс бонусов доверия в профиле.
- [ ] Пользователь видит, за что получил бонусы (история).
- [ ] В заявках помощи бонусы начисляются только после подтверждения.
- [ ] Бесплатные бонусы имеют недельный лимит (серверное время).
- [ ] Пользователь может обменять бонусы на топ-анкету / топ-услуг.
- [ ] Промо-кредиты — отдельный баланс, виден в кошельке.
- [ ] Кнопка «По вопросам рекламы» → чат с админом (копия поддержки).
- [ ] Админ может начислить кредиты из рекламного чата.
- [ ] Раздел «Бонусы и кредиты» в админ-панели с таблицей по пользователям.
- [ ] Топ-позиции имеют срок и бейдж, истекшие исчезают.
- [ ] Все операции записываются в `bonus_transactions`.
- [ ] Экран «Мої Фінанси і кредити» показывает баланс, подписки и категории трат.
- [ ] Заявки на продвижение проходят модерацию перед публикацией.
- [ ] Подписки (30 дней): уведомления за 5-4-3-2-1 дней до окончания.
- [ ] Авто-продление подписки, если хватает кредитов.
- [ ] Клиент не может изменить баланс прямой записью.
- [ ] Все начисления идемпотентны и через RTDB-транзакции.

## 13. Важные ограничения

1. Не трогать админский вход, owner-доступ, `authService.ts`, `firebase.ts`, `firebase.rules.json` без явного согласования.
2. Любое продвижение явно помечено бейджем — скрытая реклама запрещена.
3. Бонусы доверия нельзя купить за деньги. Промо-кредиты нельзя заработать бесплатно.
4. Бесплатные бонусы ограничены недельными лимитами.
5. Передача бонусов/кредитов между пользователями запрещена на первом этапе.
6. Все списания — через транзакцию с записью в историю.
7. Ограничения для новых аккаунтов привязаны к подтверждению доступа, не к дате регистрации.
